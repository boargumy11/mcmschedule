WHAT IS THIS APP?
-----------------
This is the MCM Markets CS team scheduling app.
It runs in any web browser and uses Firebase to sync
schedule data in real time across all users.

The app is made up of two key files:
  - SchedulingApp.html  -> The app itself. This is what gets hosted/deployed.
  - ScheduleApp.jsx     -> The source code. Edit this when changes are needed.

  1. Take the file SchedulingApp.html
  2. Upload it to your web server (via cPanel, FTP, etc.)
  3. Access it at yoursite.com/SchedulingApp.html
     (or rename it to index.html if you want it as the homepage)
  No additional Firebase configuration is needed.

HOW TO UPDATE THE APP (e.g. Monthly Schedule)
------------------------------------------------

PREVIOUS METHOD (Netlify -- no longer used):
  Only the original creator could update it. Required logging into
  Netlify and manually re-uploading the file each time.

CURRENT METHOD (GitHub Pages):
  Both the original creator and the manager can update the app.

  STEP 1 -- Open Claude (claude.ai) and upload ScheduleApp.jsx
    Tell Claude what you need, for example:
    "Add a blank schedule for the month of [Month Year]"

  STEP 2 -- Claude will give you an updated SchedulingApp.html
    Save this file to your computer.

  STEP 3 -- Upload the new file to GitHub
    1. Go to https://github.com/boargumy11/mcmschedule
    2. Click on SchedulingApp.html in the file list
    3. Click the pencil icon -> then the three-dot menu -> Upload file
    4. Upload the new SchedulingApp.html to replace the old one
    5. Click "Commit changes"

  STEP 4 -- Done. GitHub Pages auto-deploys within ~1 minute.
    Visit https://boargumy11.github.io/mcmschedule/ to confirm.


------------------------------------------------
EMERGENCY MEASURES (If the App Stops Working)
------------------------------------------------

If the app loads but data is not syncing or saving, check Firebase first:

  CHECK 1 -- Firebase rules not expired
    Go to: console.firebase.google.com -> sign in as boargumy11
    -> MCM Schedule -> Realtime Database -> Rules
    Both ".read" and ".write" should be set to: true
    If they show a timestamp or "false", the rules need to be
    updated back to true and republished.

  CHECK 2 -- Firebase project is active (not deleted or suspended)
    Go to: console.firebase.google.com -> sign in as boargumy11
    The "MCM Schedule" project should appear in the project list.
    If it is missing, the project may have been deleted -- contact
    the original creator to restore or recreate it.

  CHECK 3 -- Firebase usage limits not exceeded (free tier)
    Go to: console.firebase.google.com -> MCM Schedule
    -> Realtime Database -> Usage
    On the free Spark plan, the database allows 1 GB storage and
    10 GB/month download. If limits are hit, data will stop syncing
    until the next billing cycle or the plan is upgraded.

If the app itself does not load at all, check GitHub next:

  CHECK 4 -- GitHub Pages is still enabled
    Go to: github.com/boargumy11/mcmschedule -> Settings -> Pages
    It should show "Your site is live at https://boargumy11.github.io/mcmschedule/"
    If it is turned off, set Source back to: Deploy from branch -> main -> / (root)

  CHECK 5 -- The latest file upload went through correctly
    Go to: github.com/boargumy11/mcmschedule
    Click on SchedulingApp.html and check the "Last committed" timestamp.
    If it does not reflect the latest update, the upload may not have
    completed -- try uploading again.

  CHECK 6 -- GitHub Pages deployment did not fail
    Go to: github.com/boargumy11/mcmschedule -> Actions tab
    The most recent workflow run should show a green checkmark.
    If it shows a red X, the deployment failed -- try committing
    the file again to trigger a fresh deployment.
